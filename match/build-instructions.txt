3. ARCHITECTURE & STATE (CRITICAL)
----------------------------------
- ONE STATE OBJECT: keep everything the game knows in one plain object, `const state = { ... }`,
  with these fields: score, streak, learnedIds (array of fact ids), mistakes, deck (the unlearned
  facts still to play, shuffled: an array of fact OBJECTS from FACTS, never bare ids), round ({
  left: [...], right: [...] }, the fact OBJECTS whose cards are on screen in each column), selected
  ({ id, side } or null), successKeys (a Set of 'left'+id / 'right'+id keys of cards flashing
  green), failKeys (a Set of keys of cards flashing red), wrongIds (array of the ids of LEFT facts
  the player matched wrongly on the current screen; see WRONG CARDS), showInfo (boolean), isWon
  (boolean), playMs (milliseconds of playing time banked so far; see TIMER), timerStart (Date.now()
  when the running stretch of the timer began, or null when the timer is not running), timerActive
  (boolean: the player has made a move since the page loaded). Event handlers read and change
  `state` directly; there is no other copy of the game data.
- RENDERING: the screen is always drawn FROM `state`:
  - `renderRound()` builds the card elements of both columns from `state.round`. Call it ONLY when a
    new round starts (and once at start-up). Right after it, call `fitAllCards()` synchronously
    (before the browser paints).

  - `update()` brings everything else on screen in line with `state`, and MUST be called after EVERY
    change to `state`: the stats line text, the speaker button (icon, aria-label, title), the
    classes of every card on screen (.card-selected from `state.selected`, .flash-green from
    `state.successKeys`, .flash-red from `state.failKeys`, .card-wrong on each LEFT card whose id is
    in `state.wrongIds`), the How to Play panel (shown or hidden from `state.showInfo`) and the "You
    Won!" overlay (from `state.isWon`).

  - `update()` changes classes and text only. It MUST NOT rebuild the card elements, set their
    height or font size, or touch anything `fitAllCards` sets.

  - Removing matched cards: delete those two card elements from the page (and the facts from
    `state.round`). The remaining cards keep their element, size and font.

- TWO MODES (CRITICAL): one page plays either the 2 to 9 tables (the default) or the tables up to 12
  (when the page address has the argument `?12`, as in https://multiply.by/match/?12). The choice is not
  remembered: on page load only the address decides. Define, with the global constants:
  `let MODE12, GAME_NAME, FACTS, STORAGE_KEY;`
  `function applyMode(mode12) { MODE12 = mode12; GAME_NAME = mode12 ? CONFIG.GAME + '12' : CONFIG.GAME;`
  `  FACTS = mode12 ? RAW_DATA : RAW_DATA.filter(f => !/1[12]/.test(f.text));`
  `  STORAGE_KEY = 'openlang_' + CONFIG.TARGET_LANGUAGE + '_' + GAME_NAME + '_progress'; }`
  `applyMode(new URLSearchParams(window.location.search).has('12'));`
  FACTS holds 48 facts up to 12 and 36 otherwise. Everything in the game (the deck, Learned %, the

  win check, the "already finished" check at start-up) uses FACTS. RAW_DATA is read only in
  applyMode.
  applyMode also sets `document.title`: 'Multiply.by – Learn the Multiplication Table to 12 (Times
  Tables)' when mode12 is true, otherwise the page title given in section 2.

- `switchMode(mode12)` changes mode in place, WITHOUT loading a page, because a chatbot's sandboxed
  preview cannot navigate. In this order: `pauseTimer()`; `saveProgress()`; cancel every pending
  match timeout (keep their ids in a list, so feedback from the old mode cannot touch the new
  mode's cards); `applyMode(mode12)`; update the address where that is allowed:
  `try { history.replaceState(null, '', mode12 ? '?12' : window.location.pathname); } catch (e) {}`;
  reset `state` to its initial values (with the timer stopped, nothing selected, How to Play closed,
  not won); then run the same steps as start-up: read the saved progress for the new STORAGE_KEY,
  write the total, build the deck, and show "You Won!" or `startRound()` as at start-up. Finally
  call `update()`.

- Storage Key: STORAGE_KEY, set by applyMode, so each mode keeps its own saved progress.

- SAFE STORAGE (CRITICAL): Browsers can block site data (blocked cookies, privacy extensions, in-app
  browsers/WebViews, some browsers for files opened from disk). Then merely reading
  `window.localStorage` throws a SecurityError (or it is null), which would crash the game. The game
  MUST stay fully playable when storage is unavailable; progress is simply not kept.

  - In the <head>, in a small plain <script> placed IMMEDIATELY BEFORE the first other <script> tag,
    define a global object `window.safeStorage` with four methods: getItem(key), setItem(key,
    value), removeItem(key), and keys(). It behaves like localStorage, with these guarantees:
      * Every touch of `window.localStorage` (including merely reading the property) is wrapped in
        try/catch. If storage is missing or throws, the method quietly carries on.

      * It also keeps an in-memory copy of everything written. setItem always updates the copy, then
        tries localStorage. getItem tries localStorage first and falls back to the copy (null if
        neither has the key). removeItem deletes from both.

      * keys() returns the keys in localStorage, or the in-memory copy's keys when storage is
        unavailable.
      * Keys and values are always converted to strings.

      * It never throws, so the game plays normally (without saving progress) when storage is
        blocked.

  - You MUST NOT reference `localStorage` or `window.localStorage` anywhere else in the file. Every
    read, write, and removal of saved data (progress, totals, mute state) MUST use
    `safeStorage.getItem`, `safeStorage.setItem`, or `safeStorage.removeItem`. To list saved keys,
    use `safeStorage.keys()`.
  - Wrap `JSON.parse` of saved progress in try/catch; on failure, treat it as no saved data.

- Start-up: read saved progress with `safeStorage.getItem(STORAGE_KEY)`. Saved progress is the
  object `{ score, streak, learnedIds, mistakes, playMs }`; a missing `mistakes` or `playMs` field
  (progress saved by an older version) counts as 0, and any other field saved by an older version
  (such as `correct`) is ignored. Also write the total number of facts:
  `safeStorage.setItem('openlang_' + CONFIG.TARGET_LANGUAGE + '_' + GAME_NAME + '_total', FACTS.length);`

- `saveProgress()` writes `{ score, streak, learnedIds, mistakes, playMs }` from `state`, where
  playMs is `currentPlayMs()` (see TIMER), with
  `safeStorage.setItem(STORAGE_KEY, JSON.stringify(...))`.

- Deck: `state.deck` is a Fisher-Yates shuffle of the FACTS items (the fact objects themselves,
  not their ids) whose id is NOT in `state.learnedIds`. Removing or moving a fact in the deck means
  finding it by its `id` (e.g. `state.deck.filter(f => f.id !== leftId)`).

- If every fact is already learned at start-up (saved progress of a finished game), set
  `state.isWon = true` and show the "You Won!" overlay instead of a round.

- `startRound()`: take the first CARDS_PER_ROUND facts from `state.deck` (fewer if fewer are left;
  they stay in the deck until learned). Set `state.wrongIds = []` (a new screen starts with no wrong
  marks). Put them in `state.round.left` and `state.round.right`, each column shuffled independently
  with the same Fisher-Yates shuffle. Do not use a derangement or any rule that keeps an answer off
  its question's row; sometimes they will share a row, and that is fine. Clear `state.selected`,
  then call `renderRound()`, `fitAllCards()` and `update()`.
- Round end: after the matched cards are removed (see SUCCESS), check, in this order:
  1. `state.round.left` is empty: if `state.deck` still has facts call `startRound()`, otherwise
     stop the timer for good (`pauseTimer()`, then `state.timerActive = false`), set
     `state.isWon = true`, call `saveProgress()` and `update()`, then `playSound('win')`.

  2. LAST CARD REFILL: `state.round.left` holds exactly ONE fact AND `state.deck` holds at least one
     OTHER fact (one not on screen). The last pair would be matched by elimination, which teaches
     nothing, so do not make the player match it: no score, no learning, no sound. If that fact's id
     is in `state.wrongIds`, move it to the END of `state.deck` (see WRONG CARDS); otherwise leave
     it where it is in the deck (still unlearned, near the front). Then call `startRound()`, which
     deals a fresh screen at once; the leftover fact is usually on it again, unmarked, among new
     facts.

  3. Otherwise (several cards left, or the single leftover is the only fact left in the whole deck)
     the player keeps playing the screen as it is. The very last fact of the game is matched
     normally.

- TIMER ("Your time" on the "You Won!" screen): it measures PLAYING time, not the time from start to
  finish. It never shows during play.

  - `currentPlayMs()` returns `state.playMs` plus, if `state.timerStart` is not null,
    `Date.now() - state.timerStart`.

  - `startTimer()`: if the game is not won and `state.timerStart` is null and
    `document.visibilityState === 'visible'`, set `state.timerActive = true` and
    `state.timerStart = Date.now()`. Call it from a `touchstart` and a `mousedown` listener on the
    game area (both `{ passive: true }`, attached once at start-up, separate from the drag-and-drop
    listeners), so the timer starts with the player's first touch of a card and NOT when the page
    loads; reading How to Play before the first move is not counted.

  - `pauseTimer()`: if `state.timerStart` is not null, add `Date.now() - state.timerStart` to
    `state.playMs` and set `state.timerStart = null`.

  - Pause while the game is not on screen: on `visibilitychange`, when
    `document.visibilityState === 'hidden'` call `pauseTimer()` and `saveProgress()`; when it
    becomes 'visible' again and `state.timerActive` is true and the game is not won, set
    `state.timerStart = Date.now()` (the timer runs on). Also on `pagehide` call `pauseTimer()` and
    `saveProgress()`. A background tab, a locked phone or a closed page therefore adds no time.

  - Across visits: playMs is saved with the progress, so a game continued after a reload keeps
    counting from where it stopped (starting again with the first touch of a card).

  - Format (`formatTime(ms)`): whole seconds, rounded down. Under one hour M:SS (e.g. 0:47, 4:32,
    12:05); from one hour H:MM:SS (e.g. 1:02:09).

- Play Again (CRITICAL): the "You Won!" overlay shows the final score, a line "Your time: T", a line
  "Mistakes: M", and a "Play Again" button. The button MUST first set a module-level flag
  `resetting = true` (from then on `saveProgress()` returns at once without writing: the reload
  fires `pagehide`, whose save would otherwise write the finished game straight back), then clear
  the saved progress with `safeStorage.removeItem(STORAGE_KEY)`, and only then call
  `window.location.reload()`. Reloading alone would restore the finished progress, reopen on the
  "You Won!" screen, and the button would appear to do nothing. Keep the mute state (MUTE_KEY) as it
  is.

FIT TEXT TO CARD (CRITICAL): on a small or landscape screen the cards get short and narrow. Text
MUST NEVER spill outside its card: spilled text covers neighbouring cards and the header, steals
taps, and is unreadable. Cards keep their fixed height; text that does not fit is made smaller
instead.

  - Define, with the global constants, `CARD_MAX_HEIGHT` as the CSS string
    `calc((100dvh - 8.2rem) / (CARDS_PER_ROUND + 1))`, with CONFIG.CARDS_PER_ROUND + 1 filled in as
    a number. (8.2rem leaves room for the header, the stats line, the footer and the game area's
    padding.)
  - Define these helper functions:
      * `fitCardText(card)` shrinks one card's text until it fits. First reset the card's font size
        to its `data-base-font` value (so text grows back after the screen gets bigger). Then read
        the card's actual font size in pixels from its computed style (`data-base-font` is in rem,
        so do not parse it as a pixel value). Then, while the content is taller OR wider than the
        card (scrollHeight > clientHeight + 1 or scrollWidth > clientWidth + 1), reduce the font
        size by 0.5px. The font must never be smaller than 9px: if the next step would go below 9px,
        use exactly 9px and stop there, even if the text still overflows.

      * `capFontSpread(keepCaps)` evens out font sizes (see EVEN FONT SIZES). For each side
        separately, the cap is the smallest fitted font size (in px) among that side's cards on
        screen. If keepCaps is true and caps were saved earlier, each side's cap is the SMALLER of
        the saved cap and the new one, so caps never grow. Save the caps in a variable, then set
        every card on that side to its side's cap.

      * `fitAllCards()` fits every card on screen (elements with `data-side`); it does nothing when
        there are none. Run fitCardText on each card, then finish with capFontSpread: keepCaps is
        false when the round is complete on screen (just started, or no card matched yet), and true
        once any card of the round has been matched.

  - EVEN FONT SIZES: after fitting, every card on a side gets the same font size: the smallest
    fitted font on that side (left and right are capped separately), so one card does not stand out
    in larger type next to cards that had to shrink. The caps are kept while matched cards are
    removed (the remaining cards never grow), and are measured afresh for a new round, or on a
    resize while the whole round is still on screen.

  - When to fit: call `fitAllCards()` right after `renderRound()` (before the browser paints). Also
    refit, at most once per animation frame (schedule with requestAnimationFrame, cancelling any
    refit already scheduled), when the window is resized, the device rotates (orientationchange),
    the page finishes loading (load), and when web fonts are ready (`document.fonts.ready`, if
    available).

  - `fitAllCards` sets `card.style.height` and `card.style.fontSize` directly on the card elements;
    nothing else may overwrite them (see RENDERING).


5. INTERACTION & EVENTS (STRICT CONSTRAINTS)
--------------------------------------------
- TYPE CASTING (CRITICAL): ids read from the page (`data-id`) or from drag events are ALWAYS
  strings. The ids in RAW_DATA are numbers, so wrap every id read from the page in `parseInt(id)`
  before ANY game logic, strict equality (===) check, or array filtering.

- The game supports TWO ways to match, and both MUST work on every device: drag-and-drop (Systems A
  and B) and tap-to-match (System C). A first-time player must succeed with whichever one they try,
  with no instructions.
- Touch device: `const isTouchDevice = ('ontouchstart' in window) || navigator.maxTouchPoints > 0;`

- Attach every listener ONCE at start-up (on `window` for touch, on the game area for clicks and
  desktop drag, using event delegation with `e.target.closest('[data-side]')`), so cards created in
  later rounds work without new listeners.

- System A (Desktop drag-and-drop): left cards get `draggable="true"` when NOT a touch device (and
  `draggable="false"` on touch devices). Use the native `dragstart`, `dragover`, `dragleave` and
  `drop` events:
  - `dragstart` on a left card: store its id with `e.dataTransfer.setData('text/plain', id)` and
    call `clearSelection()`.

  - `dragover` on a right card: call `e.preventDefault()` (required to allow the drop) and add
    .target-hover to it. `dragleave`: remove .target-hover.

  - `drop` on a right card: `e.preventDefault()`, remove .target-hover from all cards, read the left
    card's id and call `handleMatch(leftId, rightId)`.
  - `dragend`: remove .target-hover from all cards.

- System B (Touch drag-and-drop): global `touchstart`, `touchmove`, `touchend`, `touchcancel`
  listeners on `window`, EACH ONE attached with `{ passive: false }` as its third argument, the
  `touchmove` listener above all: browsers treat a `touchmove` listener on `window` without it as
  passive and ignore its `preventDefault()`, so the browser grabs the gesture and swallows the next
  tap on a button. Use a visual clone of the card (class .drag-clone) that follows the finger. Find
  the drop target with `document.elementFromPoint()` at the finger's position (hide the clone just
  before calling it, show it again right after). Apply .target-hover to the right card under the
  finger directly with classList.

  - TAP vs DRAG (CRITICAL): on `touchstart` over ANY card, LEFT OR RIGHT (find it with
    `e.target.closest('[data-side]')`, NOT only `[data-side="left"]`), record the start coordinates,
    the card's id and side, and `moved = false` in a variable, but DO NOT create the clone yet. In
    `touchmove`, as soon as the finger is 10px or more (Euclidean distance) from the start point,
    set `moved = true` (for ANY card, left or right; it stays true until the touch ends). Create the
    clone ONLY once the finger has moved 10px or more (Euclidean distance) from the start point AND
    the touched card is a LEFT card; from then on it is a drag (call `clearSelection()` at that
    moment). In EVERY `touchmove` of a touch that started on a card (left or right, dragging or
    not), call `e.preventDefault()` if `e.cancelable` is true: the game owns that whole gesture, so
    the browser never starts scrolling, pull-to-refresh or other gestures from a card (a started
    browser gesture would also swallow the click of the next tap on a button). While dragging, move
    the clone so its center is under the finger. Only LEFT cards can be dragged; a right card that
    moves 10px or more is simply ignored (neither a tap nor a drag).

  - In `touchend`: if `moved` is still false (the finger never moved 10px), it is a TAP: call
    `e.preventDefault()` if `e.cancelable` is true (this cancels the browser's synthetic click for
    this tap; never call it on an event that cannot be cancelled, which makes the browser log an
    error), set `window._lastTouchTap = { id: parseInt(id), side, time: Date.now() }`, and call
    `handleCardTap(id, side)` for the touched card (left OR right). If a clone exists, it is a DROP:
    find the right card under the last finger position (`e.changedTouches[0]`) and, if there is one,
    call `handleMatch(leftId, rightId)`. If the finger moved but there is no clone (a right card was
    moved), do nothing at all: it is neither a tap nor a drag, and nothing gets selected.

  - FAST TAPS (CRITICAL, Android): a player often taps a left card and then its partner within a
    fraction of a second. Every tap on a card, left or right, MUST be handled by `touchend` itself;
    never rely on the synthetic click for touch taps, and never ignore clicks on OTHER cards after a
    touch tap (that silently drops the second tap of a fast match).

  - Always reset the touch-tracking variable, remove the clone and remove .target-hover from all
    cards on `touchend` and `touchcancel`.

  - Touches that do not start on a card (header buttons, links, the How to Play panel, the "You
    Won!" overlay) MUST be left completely alone: no preventDefault, so those buttons and links work
    normally.

- System C (Tap-to-Match, all devices): ONE function `handleCardTap(id, side)` handles every
  tap/click on a card.

  - It MUST begin with `id = parseInt(id);`. `selectCard(id, side)` sets
    `state.selected = { id: parseInt(id), side }` and calls `update()`; `clearSelection()` sets
    `state.selected = null` and calls `update()`.
  - Rules, in order:
    1. Ignore the tap if the How to Play panel is open (`state.showInfo`) or the game is won, or if
       the tapped card's key ('left'+id or 'right'+id) is in `state.successKeys` (it is already
       matched and about to be removed; without this a player could re-match the green cards and
       score twice).

    2. Nothing selected -> select the tapped card (left OR right; either column may be tapped
       first).
    3. Tapped the currently selected card again -> deselect it (`clearSelection()`).
    4. Tapped a different card in the SAME column -> move the selection to the tapped card.

    5. Tapped a card in the OTHER column -> attempt a match: leftId = the LEFT card's id, rightId =
       the RIGHT card's id (regardless of which was tapped first). Call `clearSelection()`, then

6. GAME LOGIC
-------------
- `handleMatch(leftId, rightId)`: parse both ids. Ignore the call if either card's key is already in
  `state.successKeys`, or if either card is no longer in `state.round`.

- MATCH VALIDATION: A match is correct if `leftId === rightId`, OR if the RIGHT card's answer text
  is exactly the same as the answer of the LEFT card's fact (two facts can share an answer, e.g. 3 x
  8 and 4 x 6 both show "24"; either "24" card is correct). Because the two cards can then have
  different ids, everything below that touches a card names it by side: the LEFT card is leftId, the
  RIGHT card is rightId.
- SUCCESS (match is correct):
  1. Call `playSound('correct')`.
  2. Increase `state.score` by (10 + `state.streak`).
  3. Increase `state.streak` by 1.

  4. If leftId is in `state.wrongIds` (the player got it wrong earlier on this screen; see WRONG
     CARDS): do NOT add it to `state.learnedIds`; move leftId from its place in `state.deck` to the
     END of `state.deck`, so it comes back at the end of the game. Then skip step 5.

     Otherwise add leftId (the LEFT card's fact) to `state.learnedIds` (if not already there). ONLY
     leftId: NEVER add rightId. Facts that share an answer are separate facts: matching 3 x 8 with
     the "24" card that belongs to 4 x 6 teaches 3 x 8 only, and 4 x 6 stays unlearned until its own
     LEFT card is matched.
  5. Remove leftId (only) from `state.deck`.
  6. Call `saveProgress()`.

  7. Green flash: add 'left'+leftId and 'right'+rightId to `state.successKeys` and call `update()`.
     The green flash shows at once (no fade) for 200ms.

  8. After a 200ms `setTimeout` (NOT longer: fast players move on immediately, and cards lingering
     on screen scramble their next move): remove both keys from `state.successKeys`, remove the LEFT
     fact leftId from `state.round.left` and the RIGHT fact rightId from `state.round.right`, delete
     those two card elements from the page, call `update()`, then check for the round end (see
     ARCHITECTURE).
- FAIL (match is not correct):
  1. Red flash on BOTH cards: add 'left'+leftId and 'right'+rightId to `state.failKeys`. Mark the
     LEFT card wrong: add leftId to `state.wrongIds` (if not already there).

  2. Set `state.streak` to 0. Decrease `state.score` by 5 (never below 0). Increase `state.mistakes`
     by 1.
  3. Call `playSound('wrong')`, `saveProgress()` and `update()`.

  4. After 2000ms, remove both keys from `state.failKeys` and call `update()`. Both cards return to
     normal; the LEFT card keeps only its small "Not learned" label.

- WRONG CARDS: a fact is learned only when its LEFT card is matched correctly on a screen where it
  was never matched wrongly. After a wrong match the LEFT card shows the small "Not learned" label
  (.card-wrong) for the rest of that screen. The player still has to match it correctly to clear it
  from the screen (normal score and streak), but it is NOT learned: it goes to the end of the deck
  and comes back, unmarked, on a fresh screen near the end of the game. Getting it wrong there sends
  it to the end again. The game is won only when every fact is learned. `state.wrongIds` is not
  saved; after a reload every unlearned fact is simply back in the shuffled deck.
