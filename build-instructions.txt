3. ARCHITECTURE & STATE (CRITICAL)
----------------------------------
- ONE STATE OBJECT: keep everything the game knows in one plain object, `const state = { ... }`,
  with these fields: score, streak, learnedIds (array of fact ids), mistakes, deck (the unlearned
  facts still to ask, shuffled: an array of fact OBJECTS from FACTS, never bare ids), question (the
  fact object on screen, or null), choices (array of the four answer strings on screen, in screen
  order), picked (index 0-3 of the answer the player tapped, or null), feedback (null, 'correct' or
  'wrong': set while the result of a tap is shown), showInfo (boolean), isWon (boolean), playMs
  (milliseconds of playing time banked so far; see TIMER), timerStart (Date.now() when the running
  stretch of the timer began, or null when the timer is not running), timerActive (boolean: the
  player has answered or touched the game since the page loaded), newBest (boolean: this game just
  set a new best score; see BEST SCORE), questionStartMs (the playing time, `currentPlayMs()`, when
  the question on screen was dealt), answerLog (the time each answer took; see ANSWER TIMES),
  practice (boolean: a PRACTICE HARD ONES round is being played), practiceIds (the ids of that
  round's facts, or an empty list). Event
  handlers read and change
  `state` directly; there is no other copy of the game data.

- RENDERING: the screen is always drawn FROM `state`:
  - `renderQuestion()` writes the question text and builds the four answer buttons from
    `state.question` and `state.choices`. Call it ONLY when a new question is dealt.

  - `update()` brings everything else on screen in line with `state`, and MUST be called after EVERY
    change to `state`: the four indicator values (see INDICATORS), the speaker button (icon, aria-label, title), the
    classes and `disabled` property of the answer buttons (see FEEDBACK), the "You Won!" texts
    (final score, time, best score, mistakes), the How to Play panel
    (shown or hidden from `state.showInfo`) and the "You Won!" overlay (from `state.isWon`).

  - `update()` changes classes, properties and text only. It MUST NOT rebuild the answer buttons.

- TWO MODES (CRITICAL): one page plays either the 2 to 9 tables (the default) or the tables up to 12
  (when the page address has the argument `?12`, as in https://multiply.by/?12). The choice is
  not remembered: on page load only the address decides. Define, with the global constants:
  `let MODE12, GAME_NAME, FACTS, STORAGE_KEY, BEST_KEY;`
  `function applyMode(mode12) { MODE12 = mode12; GAME_NAME = mode12 ? CONFIG.GAME + '12' : CONFIG.GAME;`
  `  FACTS = mode12 ? RAW_DATA : RAW_DATA.filter(f => !/1[12]/.test(f.text));`
  `  STORAGE_KEY = 'openlang_' + CONFIG.TARGET_LANGUAGE + '_' + GAME_NAME + '_progress';`
  `  BEST_KEY = 'openlang_' + CONFIG.TARGET_LANGUAGE + '_' + GAME_NAME + '_best_score'; }`
  `applyMode(new URLSearchParams(window.location.search).has('12'));`
  FACTS holds 48 facts up to 12 and 36 otherwise. Everything in the game (the deck, Learned %, the
  win check, the "already finished" check at start-up, the wrong answers) uses FACTS. RAW_DATA is
  read only in applyMode.
  applyMode also sets `document.title`: 'Multiply.by – Speed Times Tables to 12' when mode12 is
  true, otherwise the page title given in section 2.

- `switchMode(mode12)` changes mode in place, WITHOUT loading a page, because a chatbot's sandboxed
  preview cannot navigate. In this order: `pauseTimer()`; `saveProgress()`; cancel the pending
  feedback timeout, if any (keep its id in a variable, so the old mode's next question is never
  dealt into the new mode); `applyMode(mode12)`; update the address where that is allowed:
  `try { history.replaceState(null, '', mode12 ? '?12' : window.location.pathname); } catch (e) {}`;
  reset `state` to its initial values (with the timer stopped, no question, no feedback, How to Play
  closed, not won); then run the same steps as start-up: read the saved progress for the new
  STORAGE_KEY, write the total, build the deck, and show "You Won!" or `nextQuestion()` as at
  start-up. Finally call `update()`.

- Storage Keys: STORAGE_KEY and BEST_KEY, set by applyMode, so each mode keeps its own saved
  progress and its own best score.

- SAFE STORAGE (CRITICAL): Browsers can block site data (blocked cookies, privacy extensions, in-app
  browsers/WebViews, some browsers for files opened from disk). Then merely reading
  `window.localStorage` throws a SecurityError (or it is null), which would crash the game. The game
  MUST stay fully playable when storage is unavailable; progress is simply not kept.

  - In the <head>, in a small plain <script> placed IMMEDIATELY BEFORE the first other <script> tag,
    define a global object `window.safeStorage` with four methods: getItem(key), setItem(key,
    value), removeItem(key), and keys(). It behaves like localStorage, with these guarantees:
      * Every touch of `window.localStorage` (including merely reading the property) is wrapped in
        try/catch. If storage is missing or throws, the method quietly carries on.

      * It also keeps an in-memory copy of everything written. setItem always updates the copy, then
        tries localStorage. getItem tries localStorage first and falls back to the copy (null if
        neither has the key). removeItem deletes from both.

      * keys() returns the keys in localStorage, or the in-memory copy's keys when storage is
        unavailable.
      * Keys and values are always converted to strings.

      * It never throws, so the game plays normally (without saving progress) when storage is
        blocked.

  - You MUST NOT reference `localStorage` or `window.localStorage` anywhere else in the file. Every
    read, write, and removal of saved data (progress, totals, mute state) MUST use
    `safeStorage.getItem`, `safeStorage.setItem`, or `safeStorage.removeItem`. To list saved keys,
    use `safeStorage.keys()`.
  - Wrap `JSON.parse` of saved progress in try/catch; on failure, treat it as no saved data.

- Start-up: read saved progress with `safeStorage.getItem(STORAGE_KEY)`. Saved progress is the
  object `{ score, streak, learnedIds, mistakes, playMs, answerLog }`; a missing field counts as 0
  (or an empty list for learnedIds, an empty object `{}` for answerLog), and any other field is
  ignored. Also write the total number of facts:
  `safeStorage.setItem('openlang_' + CONFIG.TARGET_LANGUAGE + '_' + GAME_NAME + '_total', FACTS.length);`

- `saveProgress()` writes `{ score, streak, learnedIds, mistakes, playMs, answerLog }` from `state`, where
  playMs is `currentPlayMs()` (see TIMER), with
  `safeStorage.setItem(STORAGE_KEY, JSON.stringify(...))`.

- Deck: `state.deck` is a Fisher-Yates shuffle of the FACTS items (the fact objects themselves,
  not their ids) whose id is NOT in `state.learnedIds`. Removing or moving a fact in the deck means
  finding it by its `id` (e.g. `state.deck.filter(f => f.id !== fact.id)`).

- If every fact is already learned at start-up (saved progress of a finished game), set
  `state.isWon = true` and show the "You Won!" overlay instead of a question.

- `nextQuestion()`: set `state.feedback = null` and `state.picked = null`. If `state.deck` is empty,
  the game is won (if `state.practice` is true, the practice is done instead: see PRACTICE HARD
  ONES): stop the timer for good (`pauseTimer()`, then `state.timerActive = false`), set
  `state.question = null` and `state.isWon = true`, record the best score (see BEST SCORE), call
  `saveProgress()` and `update()`, then `playSound('win')`. Otherwise set `state.question = state.deck[0]` (it stays in the deck until it
  is answered right), set `state.choices` to a Fisher-Yates shuffle of the question's answer plus
  `wrongAnswers(state.question)`, so the right answer lands in a random one of the four places,
  set `state.questionStartMs = currentPlayMs()`, then call `renderQuestion()` and `update()`.

- WRONG ANSWERS (CRITICAL): `wrongAnswers(fact)` returns exactly three answer strings, all different
  from each other and from `fact.answer`, that are believable mistakes ("near misses"), never random
  numbers:
  1. Read the two factors a and b from `fact.text` ("6 x 8" gives a = 6, b = 8).
  2. Candidates: the products of the neighbouring facts, `(a - 1) * b`, `(a + 1) * b`, `a * (b - 1)`
     and `a * (b + 1)`, as strings. Drop any that are 0 or less, equal to `fact.answer`, or
     repeated. Shuffle the rest and keep up to three.
  3. If fewer than three are left (this happens for small facts such as 2 x 2), add the other
     distinct answers of FACTS, nearest in value to `fact.answer` first (ties in random order),
     skipping `fact.answer` and any answer already chosen, until there are three.
  For 6 x 8 (answer 48) the candidates are 40, 56, 42 and 54, and three of them are shown.

- Round end: there is no separate round end. Each screen is one question; after the feedback of a
  tap (see GAME LOGIC) `nextQuestion()` deals the next one.

- TIMER (the Time indicator next to the question, and "Your time" on the "You Won!" screen): it measures PLAYING
  time, not the time from start to finish.

  - The clock is always visible as the Time indicator during play (see INDICATORS). While the timer runs,
    a `setInterval` every 250ms (started once at start-up) calls `update()` when
    `state.timerStart !== null`, so the clock ticks. It shows 0:00 until the first touch.

  - `currentPlayMs()` returns `state.playMs` plus, if `state.timerStart` is not null,
    `Date.now() - state.timerStart`.

  - `startTimer()`: if the game is not won and `state.timerStart` is null and
    `document.visibilityState === 'visible'`, set `state.timerActive = true` and
    `state.timerStart = Date.now()`. Call it ONLY from a `pointerdown` listener on #game-area (the
    question and the answers; NOT on the whole page, the app container or the header), with
    `{ passive: true }`, attached once at start-up. So the timer starts with the player's first
    touch of the game, NOT when the page loads, and tapping RULES, the speaker or anything else in
    the header never starts it: reading How to Play first is not counted.

  - `pauseTimer()`: if `state.timerStart` is not null, add `Date.now() - state.timerStart` to
    `state.playMs` and set `state.timerStart = null`.

  - Pause while the game is not on screen: on `visibilitychange`, when
    `document.visibilityState === 'hidden'` call `pauseTimer()` and `saveProgress()`; when it
    becomes 'visible' again and `state.timerActive` is true and the game is not won, set
    `state.timerStart = Date.now()` (the timer runs on). Also on `pagehide` call `pauseTimer()` and
    `saveProgress()`. A background tab, a locked phone or a closed page therefore adds no time.

  - Across visits: playMs is saved with the progress, so a game continued after a reload keeps
    counting from where it stopped (starting again with the first touch of the game).

  - Format (`formatTime(ms)`): whole seconds, rounded down. Under one hour M:SS (e.g. 0:47, 4:32,
    12:05); from one hour H:MM:SS (e.g. 1:02:09).

- ANSWER TIMES: the game records how long each answer took, so PRACTICE HARD ONES can bring back
  the questions the player got wrong or was unsure of (slow, even when right). Nothing on screen
  shows the times.
  - `state.answerLog` is an object keyed by fact id; each value is a list of that fact's answers in
    order, each `{ ms, right }`: ms is the whole milliseconds of PLAYING time from the question being
    dealt to the tap, `Math.round(currentPlayMs() - state.questionStartMs)`, and right is true or
    false. Example: `{ "17": [{ "ms": 2350, "right": true }], "4": [{ "ms": 5120, "right": false },
    { "ms": 1890, "right": true }] }`.
  - Record it in `handleAnswer`, before the score changes, for every answer, right or wrong. Skip
    the record (not the answer) when `state.timerStart` is null at that moment: the clock has not
    started yet, so there is no time to measure (the tap that starts the clock). Also skip it while
    `state.practice` is true: the log keeps the game's answers only.
  - Because it uses playing time, time while the page is hidden is not counted.
  - It is part of the saved progress, so it survives a reload; Play Again and RESET clear it with
    the rest of the progress.

- PRACTICE HARD ONES (a short practice of the player's weakest facts, from the "You Won!" screen):
  - `weakFacts()` returns the practice set, from `state.answerLog`, as fact OBJECTS from FACTS:
    1. Every fact with at least one wrong answer, most wrong answers first (ties: the slowest
       answer first). All of them are included, even if there are more than 10.
    2. Then, until there are 10 facts, the other facts in the log, slowest first, ranked by their
       longest `ms`.
    Facts with no entry in the log are never chosen. If the log is empty, the list is empty.
  - The button "Practice hard ones" is shown on the "You Won!" screen only when `weakFacts()` is
    not empty (also for a finished game restored at start-up).
  - Tapping it starts a practice round in place, without loading a page: cancel the pending
    feedback timeout, set `state.practice = true`, `state.practiceIds` to the ids of `weakFacts()`,
    `state.deck` to a Fisher-Yates shuffle of those facts, and score, streak, mistakes, playMs to 0,
    learnedIds to [], timerStart to null, timerActive false, newBest false, isWon false; then
    `nextQuestion()`. The practice plays exactly like the game (scoring, feedback, a wrong answer
    goes to the end, the clock starts at the first touch) and the indicators show the practice:
    Learned is the percentage of `state.practiceIds` learned.
  - NOTHING of the practice is saved: `saveProgress()` returns at once without writing while
    `state.practice` is true, the best score is not touched, and answerLog does not change. The
    saved progress is still the finished game, so a reload during or after the practice opens the
    game's own "You Won!" screen again.
  - When the practice deck is empty: stop the timer (`pauseTimer()`, `state.timerActive = false`),
    set `state.question = null` and `state.isWon = true`, call `update()`, then `playSound('win')`.
    The "You Won!" overlay then shows the practice: the heading "Practice done!" instead of "You
    Won!", the lines "Your time: T" and "Mistakes: M" of the practice, and only the buttons Play
    Again and "Practice hard ones" (no score, no best score, no Share, no "up to 12" line).
    Play Again works as always (a new full game); "Practice hard ones" practises the same set
    again, in a new order.

- BEST SCORE: when a game is won, read `const best = parseInt(safeStorage.getItem(BEST_KEY));`. If
  there is no valid best yet (`isNaN(best)`) or `state.score > best`, save the new best with
  `safeStorage.setItem(BEST_KEY, state.score)` and set `state.newBest = true`. The best score is NOT
  part of the progress: Play Again and RESET keep it, and only a higher finished score replaces it.
  A finished game restored at start-up shows the saved best with `state.newBest` false. The time is
  shown on the "You Won!" screen but is never compared: finishing is winning.

- Play Again (CRITICAL): the "You Won!" overlay shows the final score, a line "Your time: T", a line
  "Mistakes: M", and a "Play Again" button. The button MUST first set a module-level flag
  `resetting = true` (from then on `saveProgress()` returns at once without writing: the reload
  fires `pagehide`, whose save would otherwise write the finished game straight back), then clear
  the saved progress with `safeStorage.removeItem(STORAGE_KEY)` (NOT BEST_KEY), and only then call
  `window.location.reload()`. Reloading alone would restore the finished progress, reopen on the
  "You Won!" screen, and the button would appear to do nothing. Keep the mute state (MUTE_KEY) as it
  is.

5. INTERACTION & EVENTS
-----------------------
- ANSWER ON TOUCH (CRITICAL): an answer counts the moment the finger or mouse button goes DOWN on it,
  not on `click`. On phones the browser cancels a click when the finger slides a little during the
  tap (it takes it for the start of a scroll or pull-to-refresh), so children would have to tap
  two or three times. Attach ONE `pointerdown` listener to #answers at start-up, using event
  delegation with `e.target.closest('.answer')`, so the buttons of later questions work without
  new listeners. If the pointer is a mouse, only the main button counts (`e.button === 0`). It
  calls `handleAnswer(parseInt(button.dataset.index))`.

- KEYBOARD: the answers are real <button> elements, so Tab, then Enter or Space, also works. Attach
  ONE `click` listener to #answers that handles ONLY clicks made by the keyboard (`e.detail === 0`)
  and ignores every other click: a tap was already answered on `pointerdown`, and its later click
  must never answer again (after a long press it would land on the NEXT question's button).

- Do NOT call preventDefault on touches: there is nothing to drag.

- Keyboard shortcut: the keys 1, 2, 3 and 4 also answer (1 is the top-left answer, 2 top-right,
  3 bottom-left, 4 bottom-right), through the same `handleAnswer`, but only while How to Play is
  closed. Use the same `keydown` listener on window as Escape.


6. GAME LOGIC
-------------
- `handleAnswer(index)`: ignore the call if the How to Play panel is open (`state.showInfo`), the game
  is won, there is no question, or feedback is being shown (`state.feedback !== null`). Otherwise
  set `state.picked = index` and record the answer's time (see ANSWER TIMES).

- ANSWER VALIDATION: the answer is right if `state.choices[index] === state.question.answer` (the
  answers are compared as strings; the four choices are always different, so exactly one is right).

- RIGHT ANSWER:
  1. Call `playSound('correct')`.
  2. Increase `state.score` by (10 + `state.streak`).
  3. Increase `state.streak` by 1.
  4. Add the question's id to `state.learnedIds` (if not already there) and remove it from
     `state.deck`.
  5. Call `saveProgress()`.
  6. Set `state.feedback = 'correct'` and call `update()` (the button turns green at once).
  7. After 200ms (a speed game: just long enough to see the green; a `setTimeout` whose id is kept
     for switchMode), call `nextQuestion()`.

- WRONG ANSWER:
  1. Call `playSound('wrong')`.
  2. Set `state.streak` to 0. Decrease `state.score` by 5 (never below 0). Increase `state.mistakes`
     by 1.
  3. The fact is NOT learned: move it from its place in `state.deck` to the END of `state.deck`, so
     it comes back at the end of the game.
  4. Call `saveProgress()`.
  5. Set `state.feedback = 'wrong'` and call `update()`: the tapped button turns red and the right
     answer turns green.
  6. After 2000ms (long enough to read the right answer; a `setTimeout` whose id is kept for
     switchMode), call `nextQuestion()`.

- MISSED QUESTIONS: a fact is learned only when it is answered right. A question answered wrongly
  goes to the end of the deck and is asked again near the end of the game (with freshly shuffled
  answers); answering it wrongly there sends it to the end again. The game is won only when every
  fact is learned. After a reload, every unlearned fact is simply back in the shuffled deck.

  `const SOUNDS = { correct: ['sine', [[660, 0, 0.08], [880, 0.08, 0.14]]], wrong: ['triangle', [[196, 0, 0.25]]], win: ['sine', [[523, 0, 0.12], [659, 0.12, 0.12], [784, 0.24, 0.12], [1047, 0.36, 0.35]]] };`
